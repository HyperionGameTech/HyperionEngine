# Wasm scripting

Plan, 2026-10-08 (revised the same day: Rust only, Strata deferred, no merge of `experiment-rust`). Nothing here is
implemented.

Goal: entity scripts written in Rust run as WebAssembly modules inside the engine, hosted by WAMR. The host layer is
generated by CodeGen, so other languages that compile to core wasm with linear memory can follow without engine
changes.

## Scope

In:

- Entity scripts (`ScriptComponent` / `ScriptAsset`) as wasm modules, added as a new script language beside C# and
  Strata.
- A wasm host layer generated by CodeGen.
- One guest language: Rust.

Out:

- Strata. It keeps its JIT and is not touched. Moving it onto wasm is in "Later".
- The `Game` class and game projects.
- C# scripts.
- The web build.
- Languages that need WasmGC, exceptions or an embedded interpreter.

## Where the code is today

- Script dispatch: `Source/Engine/Scripting/EntityScripting.cpp`. Per language it creates a `ScriptObjectResource`
  and calls `BeforeAdded(world, scene)`, `OnAdded(entity)`, `Update(delta)`, `Destroy()` by name.
- CodeGen on this branch and `dev`: `CBindingGenerator` emits one `extern "C"` thunk per reflected method, still
  shaped for Strata (registered under `HYP_STRATA`, at most two parameters, no `Handle<T>`, no string parameters).
  `BindingsShared` holds the rules for which methods and properties are bindable and how each type maps.
- `experiment-rust` (commit `8a32a8206`, unreviewed) rewrote that layer: more conventions, a manifest, struct
  layouts, a C header emitter, a Rust emitter, Rust crates and Rust game projects in the editor.

## Relationship to `experiment-rust`

Not merged. This work branches from `dev` and takes pieces from that branch only when a phase needs them, each one
read before it comes over.

The wasm host wrappers call the engine methods directly instead of wrapping the C thunks. That keeps this work
independent of the C binding layer in either of its versions, at the cost of some conversion logic that the two
layers could share later.

| From `experiment-rust` | Use here |
|---|---|
| Type rules for `Handle<T>` parameters and returns, string parameters, more than two parameters (`BindingsShared`, `Parser`) | Ported one rule at a time in phase 2 as coverage needs them |
| The shape of the typed Rust wrappers (`RustBindingGenerator`, `hyperion/src/object.rs`) | Reference for phase 4; the emitter is rewritten for wasm imports |
| `BindingLayouts` (generated struct layouts with build-time asserts) | Later, when scripts need structs beyond the math types |
| Manifest, C header emitter, `hyperion-sys` function table | Not needed |
| Rust game projects, `CallbackGame`, editor build service, templates | Not needed |

## Design

### Runtime

WAMR as a submodule in `External/Submodules`, built as a static library.

- On: fast interpreter, AOT loader, libc-builtin, bulk memory, call-stack dump.
- Off at first: WASI, threads, GC, WAMR's JITs.
- New code in `Source/Engine/Scripting/Wasm/`: runtime init, a module cache keyed by script asset, an instance wrapper
  (instance, exec env, cached export lookups).
- Guarded by `HYP_WASM_SCRIPTING`.

### Instances and contexts

One module per script crate, one instance per module, one context per entity. A crate can hold many script types.

### Guest contract

Imports, all in the default `env` module so a plain `extern` declaration works:

- every bound method, as `<Class>_<Method>`; property accessors as `<Class>_Get_<Property>` / `<Class>_Set_<Property>`
- `Hyp_Release`, `Hyp_Retain`, `Hyp_Free`, `Hyp_Log`, `Hyp_GetBindingAbiVersion`

Exports, where `<Class>` is `ScriptDesc::className`:

| Export | Purpose |
|---|---|
| `<Class>_Create() -> ctx` | new context for one entity |
| `<Class>_Destroy(ctx)` | script `Destroy`, then free the context |
| `<Class>_BeforeAdded(ctx, world, scene)` | optional |
| `<Class>_OnAdded(ctx, entity)` | optional |
| `<Class>_Update(ctx, f32 delta)` | optional |

A missing optional export is skipped. A trap marks the entity's script errored (`MarkEntityScriptErrored`) and logs
the wasm call stack; it does not take the engine down.

### ABI

| Kind | Wasm |
|---|---|
| scalar, enum | `i32` / `i64` / `f32` / `f64`; `bool` is `i32` |
| engine object, borrowed | `i64` handle id, 0 is null |
| engine object, owned by the guest (a `Handle<T>` returned by value) | `i64` handle id; released with `Hyp_Release` |
| struct in, struct returned | `i32` offset into guest memory, with a trailing out offset for returns; the host checks `offset + sizeof` against the memory size |
| string in | `i32` offset and `i32` length |
| string or scalar array returned | the host allocates in the guest's heap (`wasm_runtime_module_malloc`) and writes `{ u32 data, u32 length, u32 cap }` through a trailing out offset; the guest frees with `Hyp_Free` |

First pass covers the math types (`Vec2f/3f/4f`, `Vec2i`, `Vec2u`, `Quaternion`, `Transform`, `Name`, `Color`) as
structs, declared by hand on the Rust side with size asserts on both sides. Other structs stay unbound until
`BindingLayouts` comes over.

### Handles

A process-wide handle table. An id is `generation << 32 | index`.

- The host wrapper resolves the id before the call. A stale or wrong-type id raises a trap with a message instead of
  dereferencing.
- Entries hold a weak reference, so an id can't outlive its object unsafely. The same object always maps to the
  same id.
- Each instance keeps a list of the owned references it was given. Dropping the instance releases whatever the
  script leaked.

### Host wrappers

A new CodeGen generator (`WasmBindingGenerator`) uses `BindingsShared` to pick the bindable methods and writes, per
method, a wrapper that takes WAMR's exec env and the wasm-typed arguments, converts them (handle lookup, offset to
pointer with a size check, guest-heap allocation for out strings) and calls the method. It also writes the
`NativeSymbol` table that is registered once at startup.

The same generator writes the Rust side: the `extern "C"` import block and the typed wrappers.

### Scripts in the editor

- `ScriptLanguage::Wasm`, one value for any wasm guest.
- The compiled `.wasm` is stored as the script asset's bytecode (`ScriptAsset::SetBytecode`), so a packaged game
  carries its scripts in its assets.
- Compile: a `WasmScriptCompiler` (`ScriptCompilerBase` subclass) runs `cargo build --target wasm32-unknown-unknown`
  on the project's script crate.
- Hot reload: on a new bytecode version the engine destroys contexts, drops the instance, instantiates the new module
  and recreates contexts. Script state is lost on reload.
- UI: one more language entry in the existing New Script panel. No new panels.

## Phases

### 1. Spike

Smallest thing that proves the design. Kept only if it is clean.

1. Add WAMR, build it into the engine on Windows.
2. Hand-write five or six imports (`Hyp_Log`, an entity transform get and set, one string return, one owned handle).
3. A Rust `cdylib` guest with `Create` / `Update` / `Destroy`, loaded from a path and attached to one entity.
4. Measure: cost of one host call, cost of `Update` across 1k and 10k entities, instance memory.

Exit: the entity moves, a deliberate out-of-bounds pointer and a stale handle both trap cleanly, and the numbers are
written down.

### 2. Host generator

1. `WasmBindingGenerator` and the handle table, starting from the rules `BindingsShared` has on `dev`.
2. Lift the limits scripts will hit first, porting each rule from `experiment-rust` after reading it: `Handle<T>`
   parameters and returns, string parameters, more than two parameters.
3. A coverage report: bound, and skipped with the reason.

Verify: every wrapper compiles; a hand-written guest calls one method of each kind in the ABI table.

### 3. Engine integration

1. `ScriptObjectData_Wasm`, constructor on `ScriptObjectResource`, branches in `InvokeScriptMethodT`,
   `InitializeEntityScript`, `ShutdownEntityScript`.
2. Module cache, bytecode in the script asset, hot reload.
3. Trap handling and call-stack logging.

Verify through the editor bridge: attach, play, stop, edit, reload, twice.

### 4. Rust guest

1. A `hyperion-script` crate: the generated import block, the handle and math types, `Owned<T>` that releases on
   drop, string helpers.
2. Generated typed wrappers, one type per engine class with a safe method per binding.
3. `Script` trait and a macro that emits the `<Class>_*` exports.
4. Script crate template in `Source/Templates`, `WasmScriptCompiler`, New Script panel entry.

Verify: a script using a borrowed handle, an owned handle, a struct round trip, a string in and out, and an enum.

### 5. Using components from scripts

Scripts do not declare component types. Components are declared in the engine, in a C++ game project or in a C#
game project; a wasm script reads and writes them.

Every component, whatever declared it, is a `ComponentInterface` with a reflected `Struct` in
`ComponentInterfaceRegistry`. That registry is the single source.

1. **Mirror layout.** For each component type the host derives a plain-data mirror from its reflected fields:
   scalars, enums, math types, fixed arrays and nested structs of those are copied as they are; a handle field
   becomes an `i64` handle id; any other field (strings, containers) is left out. The mirror has its own wasm32
   layout and a hash of it.
2. **Imports.** `Entity_GetComponent(entity, typeHash, layoutHash, out)`, `Entity_SetComponent`,
   `Entity_HasComponent`, `Entity_RemoveComponent`, `Entity_AddComponent`. Get and set copy field by field following
   a plan built once per type; set leaves the fields that are not in the mirror untouched. A layout hash that does
   not match traps with a message to rebuild the script.
3. **Generated Rust.** The editor writes `components.rs` into the script crate from the live registry: one
   `repr(C)` struct per component with its type and layout hashes, used as `entity.get::<Health>()`. It is rewritten
   before each script build and when component types change (C# already raises `ComponentTypesChanged`).

Verify: a script reads and writes an engine component, one declared in a C++ game project and one declared in a C#
game project; changing a C# component's fields rebuilds the script and a stale module traps instead of corrupting
the component.

Open:

- How a C++ game project's component gets its reflected fields. The native game template has no CodeGen step that
  I could find.
- A project with scripts but no game project cannot define its own components.

### Later

- Strata on wasm: a wasm32 target and `wasm-ld` link step in stratac, component metadata and the generic component
  externs through wasm, then removal of the JIT path. Process-wide handles are already what Strata components need.
- Generated struct layouts (`BindingLayouts`).
- D: a `hyperion.d` emitter and an LDC `-betterC` template.
- AOT at package time: run `wamrc` per target platform and store `.aot` beside the `.wasm`.
- WASI switch, for toolchains that expect it. No preopened directories.
- Source-level debugging through WAMR's lldb support.
- Convergence with the C binding layer once `experiment-rust` is reviewed.
- Web build: the same guest modules, instantiated by the browser.

## Decisions to confirm

1. **Handle width.** `i64` with a generation. `i32` is cheaper for guests but makes a reused slot undetectable.
   Recommended: `i64`.
2. **Strings out.** Host allocates in the guest heap and the guest calls `Hyp_Free`. The alternative is a required
   allocator export. Recommended: host allocates.
3. **Wrappers call methods directly**, not through the C thunks. Recommended while the C layer is unreviewed.
4. **Editor execution mode.** Fast interpreter everywhere to start.

## Risks

- **Per-call overhead.** A script that calls the engine thousands of times a frame pays handle lookup and bounds
  checks on each. Phase 1 measures this before anything is built on it.
- **Weak references in the handle table** add cost per borrowed return. If it shows up, borrowed entries can become
  frame-scoped with an explicit "keep" call.
- **Two binding layers.** Wasm wrappers and C thunks each convert arguments their own way until they converge.
- **Coverage starts narrow.** The rules on `dev` bind less than `experiment-rust` does; phase 2 widens it rule by
  rule.
- **Script state is lost on hot reload** unless a script puts it in components.
- **WAMR facts taken from memory**, to check in phase 1: the guest-heap allocator behaviour when the module exports
  its own `malloc` (Rust does not by default), exec-env rules for calling from more than one thread, and the Windows
  AOT loader.
