# C bindings

Every reflected engine method that can be expressed in C gets a small C-callable function (a "thunk"), generated by
CodeGen and compiled into the engine. Strata scripts, the Rust crates and any other C-capable language call the engine
through these.

## Where things are

| What | Where |
|---|---|
| Generator | `Tools/CodeGen/Source/generator/generators/CBindingGenerator.cpp` |
| Rules shared with the Strata declaration generator | `BindingsShared.cpp` in the same folder |
| The thunks | appended to each class's `Source/Generated/**/<Header>.generated.inl` |
| Manifest of every binding | `Source/Generated/Bindings.json` |
| C header | `Source/Generated/C/hyperion_bindings.h` |
| Rust view | `Source/Generated/Rust/bindings.rs`, included by `Source/Rust/hyperion-sys` |

`Source/Generated` is a build product and is not checked in.

## Calling a binding

Bindings are not exported from the engine library one by one. Resolve each by name once:

```c
void* Hyp_ResolveBinding(const char* name);   /* e.g. "Node_GetName"; null if this build doesn't have it */
int   Hyp_GetBindingAbiVersion(void);         /* matches "abiVersion" in Bindings.json */
```

The generated header and Rust module do this for you (`HypBindings_Load`, `hyperion_sys::bindings()`).

A symbol is `<Class>_<Method>`. Property accessors without a matching method are `<Class>_Get_<Property>` and
`<Class>_Set_<Property>`. When a class overloads a method, only the first bindable overload is bound.

## Conventions (ABI version 1)

The manifest records one of these for every parameter and return.

| Convention | In C | Notes |
|---|---|---|
| `value` | the scalar itself | `bool` is one byte. An enum crosses as its underlying integer. |
| `handle` | `T*` | An engine object. Borrowed: valid while its owner keeps it alive. |
| `handle_retained` (returns only) | `T*` | The caller owns a reference and must call `Hyp_Release`. |
| `struct_ptr` | `T*` | Struct passed by pointer; the engine copies what it needs. Vectors (`Vec2f/3f/4f`) use this too. |
| `struct_out` (returns only) | trailing `T* outReturn` | The function returns `void` and writes the result through the pointer. |
| `cstring` | `const char*` | NUL-terminated UTF-8, copied by the engine. Used for `String`, `ANSIString` and `FilePath`. |
| `string_out` (returns only) | trailing `HypArray* outReturn` | `{ data, length, cap }`; free `data` with `Hyp_Free`. |
| `result` (returns only) | `bool`, plus trailing `HypArray* outError` | For a C++ `Result`. Returns whether it succeeded. On failure the message is written to `outError` (free with `Hyp_Free`); pass null to ignore it. |
| `result` with a value | `bool`, plus `outValue` and `outError` | For `TResult<T>`. On success the value is written to `outValue`, in the out form of `T`: `T*` for a scalar, enum or struct, `HypArray*` for a string, and `U**` for a `Handle<U>` (the caller owns that reference). The manifest describes `T` under `"resultValue"`. |
| `array_ptr` / `array_out` | `HypArray*` | Arrays of scalars only. An out array is freed with `Hyp_Free`. |

Instance methods take the object as their first argument.

### Ownership

A C++ method that returns `Handle<T>` by value hands the caller a reference: `handle_retained`. One that returns
`const Handle<T>&` or a raw `T*` lends the object: `handle`. `Handle<T>` parameters are always borrowed.

```c
void Hyp_Retain(void* object);
void Hyp_Release(void* object);
```

Strata has no way to release an object, so the Strata declarations leave out every `handle_retained` method. They also
leave out methods with more than two parameters, and methods that return a `Result` (an extern with an out-parameter
has to return `void` in Strata).

## What is not bound

- Methods whose signature uses a type the generator can't map: templates other than `Array<scalar>` and `Handle<T>`,
  references to scalars, string views, `void*`, a `Result` or `TResult` parameter, a `TResult` with a custom error type
  or an array value.
- Later overloads of a bound name.
- `HYP_FIELD`s that are not exposed as properties.
- Delegates and virtual overrides: bindings only go from the caller into the engine. A game written without C++ gets
  its hooks through `Hyp_CreateCallbackGame` (see `Framework/CallbackGame.hpp`).
- Structs without a layout (see below) are opaque to C and Rust: a caller can pass along a pointer it was given but
  can't allocate one.

## Struct layouts

For C or Rust to hold a struct by value it needs the struct's exact layout. Two kinds have one:

- **Hand-written**: `Vec2f`, `Vec3f`, `Vec4f`, `Vec2i`, `Vec2u`, `Name`, `StringHash`, `Color` (the math templates
  aren't reflected). They live in `hyperion-sys/src/lib.rs` and at the top of the C header.
- **Generated**: any `HYP_STRUCT` a binding passes, when CodeGen can work its layout out
  (`Tools/CodeGen/Source/generator/generators/BindingLayouts.cpp`). The struct must have no base class, and every
  `HYP_FIELD` must be a scalar, an enum, a fixed array, or another struct with a layout. `Mat4f` and `Mat3f` are
  described by hand in that file because their storage isn't a list of fields.

CodeGen computes size, alignment and field offsets itself, and the generated engine code asserts them
(`static_assert` on `sizeof`, `alignof` and each `offsetof`, in the struct's `.generated.inl`). If a struct changes so
that the computed layout is wrong, the engine build fails at that assert rather than letting C or Rust read the wrong
bytes. The usual cause is a data member that isn't a `HYP_FIELD`. Either make it one or mark the struct
`HYP_STRUCT(NoBindingLayout)`, which keeps it opaque.

A struct is left opaque without an error when CodeGen can already tell it won't work: a field of an unsupported type
(strings, handles, containers, pointers), an `alignas` that isn't a plain number, or a `HYP_STRUCT(Size = N)` that
doesn't equal the computed size.

`Bindings.json` lists the generated layouts under `"structs"`.

## Rust

`Source/Rust/hyperion-sys` is the raw layer: the value types, the lifecycle functions and `bindings()`, the generated
table.

`Source/Rust/hyperion` is what a game uses. Its `engine` module is generated too (`Source/Generated/Rust/wrappers.rs`):
one wrapper type per engine class with a safe method per binding.

| Binding side | Rust side |
|---|---|
| `Node::GetLocalTranslation` | `Node::get_local_translation(&self) -> Vec3f` |
| object parameter | `&T` (a derived wrapper or an `Owned<T>` coerces to its base) |
| borrowed object return | `Option<T>` |
| owned object return | `Option<Owned<T>>`, released on drop |
| string or path in / out | `&str` / `String` |
| `Result` return | `Result<(), String>` |
| `TResult<T>` return | `Result<T, String>`; an object is `Option<Owned<U>>` |
| scalar array in / out | `&[T]` / `Vec<T>` |
| enum | the integer alias and constants in `sys` (`sys::TransformChangeType_Default`) |

A wrapper is a borrowed pointer with no lifetime attached; `retain()` turns it into an `Owned<T>` that keeps the object
alive. A derived class dereferences to its nearest wrapped base (`Camera` → `Entity` → `Node`).

A binding is not wrapped when it takes or returns a struct without a layout, or belongs to a struct or enum rather than
a class. Those stay reachable through the raw table.

## Changing the ABI

Changing a convention changes every generated file. Bump the version in `Hyp_GetBindingAbiVersion`
(`Source/Engine/HyperionEngine.cpp`) and in the three emitters (`"abiVersion"`, `BINDING_ABI_VERSION`,
`HYP_BINDING_ABI_VERSION`) together.
